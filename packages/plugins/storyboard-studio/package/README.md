# 故事板

故事板是一个离线 Convax Web Plugin。它把一句话构思、粘贴剧本或直接连入的
Canvas 节点交给 Plugin-owned `storyboard-studio` Skill，由 Agent 在当前 Project
中建立可追踪的故事包：

```text
故事 → 分集 → 片段 → 1～3 个有序分镜
```

分镜描述单个机位；片段是最小视频生产单元，持有稳定 ID、场景设定、资产引用、
时长，以及关键帧、视频、音频的独立输出状态。Project 中的
`Storyboards/<story>/` 文件包始终是事实源。

## 生产工作台

故事索引会打开一套面向内容生产的信息密集型工作台：

- 左侧是本集/全集素材库，可切换角色、场景、素材和道具；
- 中间是当前片段的场景设定、引用资产与 1～3 个分镜脚本；
- 右侧只预览已登记的关键帧/视频，并明确显示待生成、运行中、失败或媒体缺失；
- 底部按叙事顺序展示整集片段带、时长和状态；
- 人物抽屉/专用卡展示性格、形象与图片参考、声音与音频参考、表演说明、关系和
  连续性锁，便于后续视频生成保持一致。

拖入素材、编辑片段或插入人物时，变化先停留在本地草稿。点击保存后由 Agent
重新读取事实源、保留稳定 ID 和未知兼容字段、写入最小改动并复验；插件 iframe
本身不直接写 Project 文件。

包内人物与镜头图只用于 `?demo=story` / `?demo=character`。真实 Project 故事
不会回退显示演示素材；宿主没有提供受管媒体流时，右侧只显示中性占位和受约束的
Project 相对引用，不会冒充已经播放、下载或重新验证了二进制媒体。顶部规划、清晰度、
风格与画幅会作为偏好持久化并随片段生成请求提交，但不代表已选供应方或已授权成本。

## 媒体状态与生成边界

关键帧、视频和音频分别使用
`planned`、`queued`、`running`、`ready`、`failed`、`missing-media` 状态。
`ready` 必须对应故事目录内已验证的 Project 相对路径；临时预览、已受理任务或
演示关键帧都不能冒充成片。

点击“生成片段”只会先让 Agent 说明实际可用的媒体工具/供应方、输出类型、变体数、
时长与成本相关范围。付费、批量或其他有后果的生成/合成必须再次获得用户明确确认，
完成后也只有经过持久化与复验的文件才能标记为 `ready`。

## Canvas 与宿主能力

安装后的 renderer 支持新建卡片、`*.storyboard.json` 和
`*.character.card.json`。故事索引可进入全屏工作台，人物文件可显示专用人物卡。
“展开到画布”会让 Agent 使用当前会话实际提供的公开工具，把已验证的故事、分集、
分镜和共享资产文件物化到 Canvas，并按稳定 `storyId + episodeId` 创建或复用分集组。
这个过程由多次校验操作组成，不声称原子完成。

当前公开 ABI 没有 Project 左侧栏同级目录贡献、Canvas 外的 Project 原生插件文档面，
也没有“拖入一个故事后原子展开整棵图”的声明。因此 0.1.1 使用以下诚实等价实现：

- `Storyboards/` 作为用户可见的顶层 Project 文件目录；
- 完整故事/分集/片段树位于插件工作台及其全屏形态；
- 由 Agent 负责文件写入、媒体调用和 Canvas 业务变更；
- 插件只读取获授权的当前节点、直接输入与明确引用的 Project 文本，并保存自身
  UI 状态。

包内没有本地可执行程序、隐藏 sidecar 或私有 Convax 实现。任何原生侧栏、独立文档
工作台或声明式整图物化能力都必须先进入通用、与插件 ID 无关的宿主 ABI。
